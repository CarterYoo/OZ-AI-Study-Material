## 1. 트랜스포머를 처음부터 이해하기

화면 설명

문장을 숫자로 바꾸고, 문맥을 계산하고, 다음에 올 말을 고릅니다.

발표자 노트

오늘은 트랜스포머가 문장을 만드는 과정을 입력부터 출력까지 따라가 보겠습니다. 머신러닝은 사람이 모든 규칙을 직접 쓰는 대신, 많은 예시를 보고 계산에 쓰이는 숫자를 조정하는 방법입니다. 이 숫자를 매개변수 또는 가중치라고 부릅니다. 학습은 가중치를 조정하는 과정이고, 추론은 이미 정해진 가중치로 새 입력을 계산하는 과정입니다.

예를 들어 ‘나는 아침에 빵을’이라는 문장 뒤에는 ‘먹었다’가 자연스럽습니다. 언어 모델은 이런 다음 조각의 가능성을 계산합니다. 다만 한 번에 문장 전체를 쓰는 것은 아닙니다. 작은 조각 하나를 고르고, 그 조각을 입력 뒤에 붙인 다음 다시 계산합니다.

처음 보는 수식은 외우지 않아도 됩니다. 무엇이 들어가고 무엇이 나오는지부터 보세요. 교육과정의 첫 시간에는 토큰과 임베딩, 다음 시간에는 어텐션과 내부 계산, 그다음에는 문장을 생성하는 방법에 집중하면 됩니다. 이 자료는 그 전체 흐름을 담고 있습니다.

확인 질문
학습과 추론은 무엇이 다른가요?
답변 예시
학습에서는 가중치를 바꾸고, 추론에서는 배운 가중치를 이용해 입력을 처리합니다.

## 2. ChatGPT 같은 언어 모델은 어떻게 작동할까요?

화면 설명

출력은 완성된 문장이 아니라, 다음 토큰 후보들의 확률입니다.

발표자 노트

먼저 ‘모델’은 입력을 받아 계산 결과를 내는 프로그램이라고 생각하세요. 트랜스포머는 그 프로그램의 내부 구조입니다. 여기서는 GPT 계열처럼 앞의 내용을 보고 다음 토큰을 예측하는 구조를 다룹니다. 실제 대화 서비스에는 추가 학습과 여러 기능이 더해져 있습니다.

토큰은 글을 나눈 작은 조각입니다. 한 단어일 수도 있고, 단어의 일부나 문장부호일 수도 있습니다. 모델은 토큰 목록을 입력받고 다음에 올 수 있는 각 토큰에 점수를 줍니다. 이 점수를 확률로 바꾸면 모든 후보의 확률 합이 1, 즉 100%가 됩니다. 오른쪽 그래프의 막대가 높을수록 해당 후보를 더 높은 확률로 예측한다는 뜻입니다. 표시된 후보들은 전체 어휘 중 일부입니다.

매개변수는 모델이 학습 중 조정하는 숫자입니다. 작은 GPT2도 약 1억 2,400만 개를 사용합니다. 이를 각각 4바이트로 저장하면 가중치만 약 496MB이며, 실제 실행에는 추가 메모리가 필요합니다. 학습용 글의 양과 매개변수 개수는 서로 다른 수치입니다. 원본의 학습 데이터 수치는 공식 공개 자료에 맞춰 약 40GB의 텍스트로 정정했습니다.

답변 예시
아닙니다. 다음에 그 토큰이 나올 것으로 모델이 예측하는 정도입니다.

## 3. 글을 토큰과 번호로 바꾸기

화면 설명

토큰은 글의 조각이고, 토큰 ID는 그 조각에 붙인 번호입니다.

발표자 노트

왼쪽에서 색이 나뉘는 부분을 보세요. 각각이 하나의 토큰입니다. 사람이 띄어쓰기로 나눈 단어와 모델이 나눈 토큰은 반드시 같지 않습니다. 흔한 단어는 한 토큰으로 묶일 수 있고, 낯선 단어나 한국어 표현은 여러 조각으로 나뉠 수 있습니다. 공백이 뒤 단어와 함께 묶이는 경우도 있습니다.

그 아래의 숫자 목록은 토큰 ID입니다. 도서관의 책 번호처럼 어떤 조각인지 찾기 위한 표지입니다. 100번 토큰이 50번 토큰보다 의미가 두 배 크다는 뜻은 아닙니다. 이 번호를 그대로 의미 있는 크기로 계산하지 않고, 뒤에서 배울 임베딩 표에서 숫자 묶음을 찾아옵니다.

같은 문장을 넣어도 GPT2와 Mistral의 결과가 다른 이유는 토큰을 나누는 규칙과 번호표가 다르기 때문입니다. 슬라이드의 토크나이저 링크에서 짧은 영어 문장과 한국어 문장을 각각 넣어 보세요. 코드 화면의 영어 예문과 함수 이름은 실제 실행 예시이므로 그대로 읽습니다.

확인 질문
같은 ID가 서로 다른 모델에서도 같은 글을 뜻할까요?
답변 예시
꼭 그렇지는 않습니다. 해당 모델의 토크나이저와 어휘표를 함께 사용해야 합니다.

## 4. 토크나이저와 어휘표

화면 설명

어휘표는 글 조각과 번호를 연결합니다. 의미를 학습하는 표와는 다릅니다.

발표자 노트

어휘표는 사용할 수 있는 토큰과 각 토큰의 번호를 모은 표입니다. 오른쪽의 cat, cattle, car, carp 예시는 문자 조각을 정수에 대응시키는 개념을 보여 줍니다. 여기의 번호는 설명을 위한 예시이며 실제 GPT2의 번호가 아닙니다.

왼쪽 그림은 공통된 앞부분을 공유하는 문자열을 가지 모양으로 저장한 것입니다. 이런 자료구조를 트라이라고 합니다. C 다음 A까지는 같은 길을 따라가고, 이후 글자에 따라 가지가 갈라집니다. 오늘은 구현법보다 ‘어떤 조각들이 사전에 있는가’를 떠올리는 보조 그림으로 보면 충분합니다.

GPT2는 바이트 쌍 인코딩, 줄여서 BPE라는 방식으로 토큰을 만듭니다. 자주 함께 등장하는 작은 조각들을 정해진 순서에 따라 합치는 방식입니다. 토크나이저는 언어 모델을 학습하기 전에 준비하고 보통 고정합니다. 뒤에서 만날 임베딩 표의 숫자들은 모델 학습 중 바뀐다는 점과 구분하세요.

확인 질문
어휘표와 임베딩 표는 같은 표인가요?
답변 예시
아닙니다. 어휘표는 조각과 ID를 연결하고, 임베딩 표는 ID와 학습된 벡터를 연결합니다.

## 5. 토크나이저의 세부 사항

화면 설명

오늘은 준비된 GPT2 토크나이저를 사용하고, 입력과 출력의 의미에 집중합니다.

발표자 노트

앞 장의 그림을 조금 더 자세히 보겠습니다. 트라이는 사전에 있는 문자열을 빠르게 찾는 데 쓸 수 있습니다. 다만 그림처럼 가장 긴 문자열을 고르는 절차가 모든 토크나이저의 실제 알고리즘인 것은 아닙니다. GPT2의 BPE는 미리 정한 병합 우선순위를 따릅니다. 이 둘을 같은 방식으로 외우지 마세요.

토크나이저에는 일반 글 조각 외에 특별한 용도의 토큰이 있을 수 있습니다. 예를 들어 문서 경계를 표시하는 토큰입니다. 어떤 종류가 있는지는 모델마다 다릅니다. 특히 GPT2의 바이트 기반 방식은 일반적인 미등록 단어용 토큰이 꼭 필요한 구조는 아닙니다. 처음 보는 단어도 더 작은 조각으로 표현할 수 있습니다.

실습에서는 모델에 맞는 토크나이저를 불러와 글을 ID 목록으로 바꾸고, 다시 글로 돌려보는 데 집중합니다. 이 과정에서 모델이 받는 입력은 문자열 자체가 아니라 정수 목록이라는 점을 확인하세요. 토크나이저를 처음부터 구현하는 것은 오늘의 필수 목표가 아닙니다.

확인 질문
처음 보는 단어가 나오면 반드시 입력할 수 없게 되나요?
답변 예시
아닙니다. 더 작은 조각들로 나눠 표현할 수 있습니다.

## 6. 입력의 각 위치에서 다음 토큰을 예측하기

화면 설명

학습할 때는 여러 위치의 다음 토큰을 함께 예측하되, 미래의 정답은 가립니다.

발표자 노트

아래에서 위로 그림을 읽어 봅시다. 입력은 ‘The cat sat on the mat’처럼 순서가 있는 토큰 목록입니다. 가운데 상자가 트랜스포머이고, 위의 각 세로 막대는 해당 위치에서 계산한 출력입니다. 막대 하나는 숫자 하나가 아니라 어휘 전체에 대한 점수 목록을 뜻합니다.

‘The’ 위치의 출력은 그다음 토큰을 예측합니다. ‘cat’ 위치의 출력은 ‘The cat’까지 보고 다음을 예측합니다. 이렇게 각 위치에 다음 토큰 맞히기 문제가 하나씩 생깁니다. 학습용 문장을 통째로 알고 있더라도, 해당 위치가 뒤의 정답을 엿보지 못하도록 계산 연결을 막습니다. 이 장치를 뒤에서 인과 마스크라고 부릅니다.

학습에서는 여러 위치의 정답을 이미 알고 있으므로 여러 예측을 한꺼번에 계산해 비교할 수 있습니다. 새 글을 생성할 때는 아직 다음 토큰이 정해지지 않았으므로 마지막 위치의 예측으로 하나를 고르고 다시 계산합니다. 학습의 병렬 계산과 생성의 순차 진행을 구분하는 것이 중요합니다.

확인 질문
‘cat’ 위치에서 ‘mat’을 미리 참고해도 될까요?
답변 예시
안 됩니다. 실제 생성 시점에는 아직 주어지지 않은 미래 정보입니다.

## 7. RNN과 트랜스포머의 차이

화면 설명

RNN은 앞 단계 계산을 기다립니다. 트랜스포머는 학습 중 여러 위치를 함께 계산합니다.

발표자 노트

왼쪽의 고리는 같은 계산을 반복한다는 표시입니다. 오른쪽은 이 반복을 시간 순서대로 펼쳐 놓은 그림입니다. x는 이번에 들어온 입력이고, h는 이전까지 읽은 내용을 담은 내부 상태입니다. A라는 같은 계산 장치를 여러 시점에 사용합니다.

RNN에서는 앞의 h가 있어야 다음 h를 계산할 수 있습니다. 앞 사람이 계산을 끝내야 다음 사람이 이어받을 수 있는 줄서기와 비슷합니다. 서로 다른 문장들을 묶어 계산할 수는 있지만, 한 문장 안에서 시점 사이의 의존성이 남습니다.

트랜스포머는 어텐션을 이용해 토큰 사이의 관계를 계산합니다. 학습할 때는 주어진 문장의 여러 위치를 한꺼번에 처리하기가 좋습니다. 하지만 GPT처럼 새 토큰을 하나씩 생성하는 과정은 트랜스포머도 순차적입니다. ‘트랜스포머는 언제나 문장 전체를 동시에 생성한다’는 뜻으로 받아들이면 안 됩니다.

확인 질문
트랜스포머가 학습을 병렬로 한다면, 생성할 때 미래 토큰도 이미 알고 있나요?
답변 예시
아닙니다. 생성할 토큰은 하나씩 선택됩니다.

## 8. 다음 토큰을 골라 문장 이어 쓰기

화면 설명

예측 → 하나 선택 → 입력 뒤에 붙이기. 이 과정을 반복하면 문장이 됩니다.

발표자 노트

입력 문장을 토큰으로 나눈 뒤 모델에 넣습니다. 모델이 돌려주는 것은 다음 토큰 후보마다 계산한 확률입니다. 이제 이 확률에서 실제로 어떤 토큰 하나를 선택할지 결정해야 합니다. 선택하는 절차를 샘플링이라고 합니다.

가장 확률이 높은 토큰만 고르는 방법은 간단합니다. 하지만 항상 같은 선택을 하므로 반복적인 결과가 나올 수 있습니다. 확률에 따라 무작위로 고르면 같은 입력에서도 다른 결과가 나올 수 있습니다. 예를 들어 A가 80%, B가 20%라면 같은 분포에서 매우 많이 뽑았을 때 대략 그 비율로 선택됩니다. 열 번마다 정확히 여덟 번이라는 뜻은 아닙니다.

온도는 분포가 얼마나 뾰족하거나 고른지를 조절합니다. 온도를 높이면 낮은 확률의 후보에도 기회가 더 돌아갈 수 있습니다. 그렇다고 사실성이나 창의성이 자동으로 좋아지는 것은 아닙니다. 고른 토큰을 기존 입력 뒤에 붙이고, 그다음 토큰을 다시 예측합니다. 종료 토큰이나 정해 둔 길이에 도달하면 멈춥니다.

확인 질문
같은 모델이 같은 질문에 다른 답을 하는 이유는 무엇일까요?
답변 예시
확률에 따라 토큰을 고르는 과정에서 다른 선택을 할 수 있기 때문입니다.

## 9. 전체 구조와 잔차 연결

화면 설명

기존 정보를 유지하면서, 어텐션과 MLP가 계산한 내용을 차례로 더합니다.

발표자 노트

이 그림은 아래에서 위로 읽습니다. 토큰은 먼저 임베딩을 거쳐 벡터가 됩니다. 벡터는 순서대로 놓인 숫자 묶음입니다. 숫자가 768개라면 768차원 벡터라고 부릅니다. 각 숫자가 반드시 ‘고양이 여부’ 같은 사람이 아는 개념 하나와 대응하는 것은 아닙니다.

세로로 곧게 이어진 길을 잔차 스트림이라고 부릅니다. 지금까지 계산한 정보를 들고 가는 공용 메모장으로 생각하면 됩니다. 옆의 어텐션과 MLP는 이 메모장을 읽고, 새로 계산한 숫자 묶음을 다시 더합니다. 덧셈은 같은 위치의 숫자끼리 더하는 연산입니다. 기존 정보를 모두 지우고 새 결과로 교체하는 구조가 아닙니다.

위쪽의 언임베딩은 최종 벡터를 어휘별 점수로 바꿉니다. 이 점수를 로짓이라고 하며, 아직 확률은 아닙니다. 소프트맥스를 적용해야 합이 1인 확률이 됩니다. 그림은 흐름을 단순화했으므로 GPT2의 위치 임베딩과 정규화 같은 세부 요소는 뒤 그림에서 보충합니다.

확인 질문
x + f(x)에서 x를 다시 더하는 이유를 어떻게 설명할 수 있을까요?
답변 예시
이전 정보를 이어 가면서 새 계산 결과를 보태기 위해서입니다.

## 10. 토큰의 의미와 위치를 숫자로 표현하기

화면 설명

발표자 노트

토큰 ID는 단순한 번호이므로 그대로는 풍부한 정보를 담기 어렵습니다. 임베딩 표에는 각 ID에 대응하는 벡터가 들어 있습니다. ID를 행 번호로 사용해 해당 행의 숫자 묶음을 꺼내는 것이 토큰 임베딩입니다. 이 표의 숫자들은 학습 중 조정됩니다.

문장에서는 순서도 중요합니다. ‘개가 사람을 물었다’와 ‘사람이 개를 물었다’는 등장하는 말은 비슷해도 뜻이 다릅니다. GPT2에서는 위치마다 준비된 벡터를 토큰 벡터에 더합니다. 두 벡터의 길이는 같아야 합니다. 이어 붙여 길이를 두 배로 만드는 것이 아니라 같은 칸끼리 더합니다. 다른 모델은 위치를 다른 방식으로 표현하기도 합니다.

이 벡터들은 여러 트랜스포머 블록을 지나며 문맥 정보를 반영합니다. 마지막에는 언임베딩으로 토큰별 점수를 얻고, 소프트맥스로 확률을 만듭니다. 소프트맥스는 각 점수에 지수함수를 적용한 뒤 그 합으로 나누는 계산입니다. 지금은 ‘점수 목록을 확률 목록으로 바꾼다’는 역할부터 기억하면 됩니다.

## 11. 트랜스포머 블록 안의 두 가지 계산

화면 설명

어텐션은 다른 위치의 정보를 모으고, MLP는 각 위치의 정보를 가공합니다.

발표자 노트

블록은 반복해서 쌓는 하나의 계산 단위입니다. 이 그림의 GPT2형 블록에서는 먼저 정규화한 정보를 어텐션에 넣고 그 결과를 원래 흐름에 더합니다. 이어서 다시 정규화한 정보를 MLP에 넣고 그 결과도 더합니다. 파란 세로선이 기존 정보를 계속 전달하는 잔차 스트림입니다.

어텐션은 현재 위치가 앞의 어느 위치를 얼마나 참고할지 계산합니다. 예를 들어 ‘민수가 사과를 샀다. 그는’에서 ‘그는’을 처리할 때 ‘민수’에 관한 정보가 도움이 될 수 있습니다. MLP는 각 위치에 모인 숫자들을 가공합니다. MLP 단계 자체가 다른 위치의 벡터를 직접 가져오는 것은 아닙니다. 다만 앞선 어텐션이 이미 문맥을 섞어 놓았을 수는 있습니다.

한 번의 블록으로 끝내지 않고 여러 블록을 쌓으면 이전 단계의 결과를 다음 단계가 다시 활용할 수 있습니다. 정규화는 숫자의 크기를 다루기 쉽게 조정하는 과정이며, 자세한 계산은 다음 장에서 봅니다. 그림의 덧셈 동그라미를 따라가며 어떤 값이 유지되고 무엇이 더해지는지 확인하세요.

확인 질문

답변 예시
어텐션입니다.

## 12. MLP의 계산 순서

화면 설명

숫자를 섞어 넓히고, 비선형 함수를 거친 뒤, 원래 길이로 되돌립니다.

발표자 노트

MLP는 여러 숫자를 입력받아 새로운 숫자 묶음을 계산하는 작은 신경망입니다. 그림의 첫 선형층은 입력 숫자들을 가중치를 곱해 더하는 방식으로 섞습니다. 행렬은 이런 가중치들을 표 모양으로 모은 것입니다. 편향은 계산 결과에 더하는 학습 가능한 상수입니다.

중간의 활성화 함수는 각 숫자를 비선형적으로 바꿉니다. 단순히 직선 하나로 나타낼 수 없는 변환을 넣어 표현할 수 있는 관계를 늘리는 것입니다. GPT2에서는 GELU 계열의 함수를 사용합니다. 아래 곡선은 큰 양수는 비교적 통과시키고 음수는 부드럽게 줄이는 모습을 보여 줍니다. 적분식을 외울 필요는 없습니다.

마지막 선형층은 벡터를 원래 길이로 되돌립니다. 그래야 잔차 스트림에 더할 수 있습니다. 그림의 batch는 함께 처리하는 문장 수, seq는 문장 안의 토큰 수, d_model은 토큰당 숫자 개수입니다. d_mlp는 MLP 중간 단계의 숫자 개수이며 GPT2에서는 보통 d_model의 네 배입니다. MLP는 위치마다 같은 가중치를 사용합니다.

확인 질문
마지막 출력 길이를 d_model로 맞추는 이유는 무엇인가요?
답변 예시
원래 벡터와 같은 칸끼리 더해야 하기 때문입니다.

## 13. 하나의 숫자 칸에 하나의 개념만 들어갈까요?

화면 설명

여러 특징이 같은 벡터 공간을 겹쳐 사용할 수 있습니다. 이 장은 선택 심화입니다.

발표자 노트

이 장은 트랜스포머를 구현하기 위한 필수 내용은 아닙니다. 벡터의 각 칸이 하나의 개념과 딱 맞아떨어질 것이라는 오해를 풀기 위한 이야기입니다. 처음 듣는다면 ‘여러 특징이 여러 숫자에 걸쳐 나타날 수 있다’는 점만 기억하고 넘어가도 됩니다.

평면에서 서로 직각인 방향은 두 개, 3차원 공간에서는 세 개까지 고를 수 있습니다. N차원에서도 서로 직교하는 0이 아닌 벡터는 최대 N개입니다. 하지만 완전히 직각이어야 한다는 조건을 느슨하게 하면, 서로 조금씩 겹치는 방향을 훨씬 많이 놓을 수 있습니다. 관련 수학은 고차원 공간이 많은 정보를 구별하는 데 유용하다는 직관을 줍니다.

모델이 차원 수보다 많은 특징을 겹쳐 표현하는 현상을 중첩이라고 부릅니다. 다만 겹침에는 간섭이 생기고, 어떤 조건에서 유리한지가 중요합니다. 단순한 기하학만으로 ‘모델이 커지면 반드시 성능이 좋아진다’고 결론 낼 수는 없습니다. 원본의 대략적인 지수식은 조건을 생략한 표현이어서 여기서는 정리의 정확한 공식으로 제시하지 않습니다.

## 14. MLP와 활성화 함수

화면 설명

연결선의 가중치와 비선형 변환을 함께 사용해 입력 정보를 가공합니다.

발표자 노트

왼쪽 원 하나는 계산 중인 숫자 하나를 나타냅니다. 아래 입력층에서 가운데 은닉층으로 갈 때, 연결선마다 가중치를 곱하고 결과를 더합니다. ‘은닉’은 특별히 비밀이라는 뜻이 아니라 입력과 출력 사이의 중간 계산 단계라는 뜻입니다.

수식은 안쪽부터 읽습니다. W1x + b1로 숫자를 섞고, σ라는 활성화 함수를 적용한 뒤, W2와 b2로 다시 변환합니다. W는 가중치 행렬, b는 편향입니다. 둘 다 학습할 때 조정됩니다. 이 장의 σ는 활성화 함수를 일반적으로 나타내는 기호이지, 반드시 시그모이드 함수를 뜻하지는 않습니다.

활성화 함수가 없다면 선형 변환을 여러 번 해도 하나의 선형 변환으로 합칠 수 있습니다. 중간에 비선형 변환을 넣어 더 다양한 관계를 표현하게 합니다. GELU와 ReLU는 비슷한 직관을 줄 수 있지만 같은 함수는 아닙니다. 원본의 근사 표시는 모양의 직관으로만 읽고 등식으로 외우지 마세요. Φ는 표준정규분포의 누적확률이며, 오늘은 계산법보다 함수가 하는 역할에 집중합니다.

확인 질문

답변 예시

## 15. 층 정규화로 숫자의 크기 조절하기

화면 설명

한 토큰의 숫자 묶음을 정규화한 뒤, 학습된 크기와 이동량을 적용합니다.

발표자 노트

같은 정보를 담더라도 숫자의 크기가 매우 들쭉날쭉하면 학습 중 계산을 다루기 어려울 수 있습니다. 층 정규화는 각 토큰의 벡터 안에서 평균과 분산을 계산해 규모를 조절합니다. 서로 다른 문장이나 여러 토큰 전체를 한꺼번에 평균 내는 것이 아닙니다.

먼저 각 숫자에서 평균을 빼 중심을 0 근처로 맞춥니다. 다음에는 분산에 작은 양수 ε를 더한 값의 제곱근으로 나눕니다. ε는 분산이 아주 작을 때 계산을 안정적으로 하기 위해 넣습니다. 이 단계까지는 평균이 0, 분산이 대략 1이 되도록 조정됩니다.

마지막으로 학습 가능한 γ를 곱하고 β를 더합니다. 따라서 최종 출력의 평균과 분산이 언제나 정확히 0과 1인 것은 아닙니다. 원본의 표현은 이 마지막 단계를 빠뜨릴 수 있어 보충했습니다. 그림에서는 정규화 결과를 어텐션이나 MLP에 보내고, 원래 잔차 흐름에는 그 계산 결과를 더합니다.

답변 예시
아닙니다. 각 토큰의 벡터를 따로 정규화하며 벡터 길이도 유지합니다.

## 16. 어텐션 한 개의 계산

화면 설명

Q와 K로 참고할 비율을 정하고, 그 비율로 V를 섞습니다.

발표자 노트

어텐션은 여러 위치의 정보를 필요한 만큼 가져오는 계산입니다. 각 위치의 벡터에서 세 가지 벡터를 만듭니다. Q인 쿼리는 지금 어떤 정보가 필요한지, K인 키는 자신이 어떤 정보와 맞는지, V인 값은 실제로 전달할 내용을 나타낸다고 비유할 수 있습니다. 셋 모두 실제로는 학습된 가중치로 만든 숫자 묶음입니다.

현재 위치의 Q와 각 위치의 K를 내적해 점수를 계산합니다. 내적은 같은 칸끼리 곱한 뒤 더하는 계산입니다. 점수가 클수록 이 계산에서 서로 잘 맞는다는 뜻입니다. 벡터 길이의 제곱근으로 나눠 크기를 조절하고, 미래 위치를 가린 뒤 소프트맥스로 각 위치를 참고할 비율을 만듭니다.

이 비율로 V들을 가중합합니다. 예를 들어 두 위치의 비율이 0.75와 0.25라면 결과는 0.75V1 + 0.25V2입니다. 한 위치만 선택해 그대로 복사하는 것은 아닙니다. 마지막 W_O 변환으로 잔차 스트림에 더할 수 있는 길이로 바꿉니다. 오른쪽 간단한 공식은 마스크와 최종 출력 변환을 생략한 핵심 부분입니다.

확인 질문
확률처럼 보이는 어텐션 비율은 다음 단어의 확률인가요?
답변 예시
아닙니다. 여기서는 입력의 어느 위치를 얼마나 참고할지 나타내는 비율입니다.

## 17. 미래를 보지 못하게 하는 인과 마스크

화면 설명

현재 위치는 자기 자신과 앞의 토큰만 참고할 수 있습니다.

발표자 노트

학습할 때는 문장 전체가 입력에 들어 있습니다. 아무 제한이 없다면 다음 토큰을 예측해야 하는 위치가 정답을 미리 읽어 버릴 수 있습니다. 그래서 현재 위치보다 뒤에 있는 토큰을 참고하지 못하도록 막습니다. 이 장치가 인과 마스크입니다.

표에서 행은 정보를 요청하는 현재 위치, 즉 쿼리입니다. 열은 참고할 위치, 즉 키입니다. 행보다 더 뒤에 있는 열의 점수를 매우 작은 값, 수학적으로는 음의 무한대로 둡니다. 그러면 소프트맥스 이후 그 칸의 비율이 0이 됩니다. 마스킹은 소프트맥스 전에 적용해야 한다는 순서도 기억하세요.

대각선은 자기 자신이므로 남겨 둡니다. 현재 토큰을 입력으로 알고 있으면서 다음 토큰을 예측하는 것이기 때문입니다. 한 행에서 허용된 칸들의 비율 합은 1입니다. 예를 들어 세 번째 토큰은 첫째, 둘째, 셋째 위치를 참고할 수 있지만 넷째는 볼 수 없습니다.

확인 질문
세 번째 위치에서 다섯 번째 위치로 가는 참고 비율은 얼마인가요?
답변 예시
0입니다. 아직 볼 수 없는 미래 위치이기 때문입니다.

## 18. 질문과 답변으로 이해하는 어텐션

화면 설명

질문 Q와 설명표 K가 잘 맞는 곳에서, 전달할 내용 V를 가져옵니다.

발표자 노트

그림 속 사람은 토큰 위치를 나타냅니다. 각 사람은 자기 앞에 있는 말들을 참고해 다음 말을 예측하려고 합니다. 말풍선의 질문은 Q, 어떤 질문에 답할 수 있는지를 나타내는 표지는 K, 실제 전달하는 내용은 V에 해당합니다. 이 비유는 계산의 역할을 구별하기 위한 것이며, 모델 내부에서 사람이 읽는 질문 문장이 만들어진다는 뜻은 아닙니다.

‘The sky is’라는 예시에서는 ‘is’ 위치가 앞의 ‘sky’에서 정보를 가져오면 다음 단어를 예측하는 데 도움이 될 수 있습니다. Q와 K로 관련성을 점수화하고, 소프트맥스로 비율을 만든 뒤, V들을 그 비율로 섞습니다. 자기 자신에게서도 정보를 받을 수 있습니다.

오른쪽 표의 가로와 세로를 확인하세요. 여러 질문이 여러 키와 각각 비교됩니다. 미래를 가린 빨간 표시가 있는 칸은 사용할 수 없습니다. 다만 실제 모델의 각 헤드가 반드시 ‘하늘의 색’을 찾는 식으로 사람이 이름 붙일 수 있는 역할을 갖는 것은 아닙니다.

확인 질문
Q, K, V 중 실제로 섞어 전달하는 벡터는 무엇인가요?
답변 예시
V입니다. Q와 K는 그 정보를 섞을 비율을 정하는 데 쓰입니다.

## 19. 어텐션과 MLP를 구분하기

화면 설명

어텐션으로 다른 위치의 정보를 모으고, MLP로 모인 정보를 처리합니다.

발표자 노트

왼쪽 그림의 사람들은 앞의 사람들에게 질문할 수 있습니다. 이것이 토큰 사이에서 정보를 모으는 어텐션의 비유입니다. 질문과 설명표가 잘 맞는 정도에 따라 여러 사람의 전달 내용을 섞습니다. ‘The sky is’ 다음에 무엇이 올지 생각할 때 앞의 문맥을 가져오는 단계입니다.

오른쪽 위의 전구 그림은 자기 자리에 있는 정보를 가공하는 MLP를 나타냅니다. 다른 사람에게 새로 질문하는 단계가 아니라, 이미 받은 정보와 원래 있던 정보를 이용해 새 결과를 계산합니다. 각 위치에서 같은 MLP를 적용하지만 입력 벡터가 다르므로 결과는 달라집니다.

여기서 ‘MLP가 다른 토큰을 직접 보지 않는다’와 ‘문맥을 전혀 이용하지 않는다’를 구분해야 합니다. 앞선 어텐션을 거친 벡터에는 다른 위치의 정보가 이미 들어 있을 수 있습니다. 여러 블록을 지나면 정보를 모으는 단계와 가공하는 단계가 반복됩니다.

확인 질문
MLP의 입력에 앞 단어의 정보가 들어 있을 수 있나요?
답변 예시
있습니다. 이전 어텐션이 그 정보를 현재 위치로 가져왔을 수 있습니다.

## 20. 여러 어텐션 헤드를 함께 쓰기

화면 설명

여러 헤드가 각자의 비율로 정보를 모으고, 결과를 합쳐 다음 단계에 전달합니다.

발표자 노트

왼쪽은 헤드 하나이고, 오른쪽은 여러 헤드를 함께 계산하는 모습입니다. 헤드는 독립된 Q, K, V 가중치를 가진 어텐션 계산 단위입니다. 같은 입력을 받더라도 각 헤드의 가중치가 다르므로 어떤 위치를 참고하는지가 달라질 수 있습니다.

여러 사람이 같은 글을 서로 다른 관점에서 읽는다고 비유할 수 있습니다. 하지만 사람이 미리 ‘너는 문법, 너는 의미’를 배정하는 것은 아닙니다. 어떤 계산을 하게 될지는 학습으로 정해집니다. 각 헤드가 만든 결과를 출력 변환을 통해 원래 벡터 공간으로 옮겨 합칩니다.

구현에서는 헤드 결과를 이어 붙인 뒤 큰 출력 행렬을 곱하는 표현도 자주 씁니다. 이 그림처럼 각 헤드의 출력 변환을 나누어 합하는 표현과 같은 계산으로 볼 수 있습니다. b는 묶음의 문장 수, s는 토큰 수, n은 헤드 수, h는 헤드 안의 벡터 길이, e는 잔차 벡터 길이입니다. 표기마다 h의 뜻이 달라질 수 있으니 코드에서는 d_head처럼 이름을 확인하세요.

확인 질문
헤드가 여러 개면 반드시 서로 다른 언어적 역할을 맡나요?
답변 예시
그렇게 보장되지는 않습니다. 서로 다른 정보를 활용할 가능성을 주는 구조입니다.

## 21. 어텐션의 다섯 단계 다시 보기

화면 설명

Q·K·V 만들기 → 점수 계산 → 미래 가리기 → 비율로 V 섞기 → 출력 변환

발표자 노트

복잡한 식 대신 다섯 단계로 다시 말해 보겠습니다. 첫째, 각 위치의 벡터에서 Q, K, V를 만듭니다. 둘째, 현재 Q와 각 K를 비교해 점수를 만들고 크기를 조절합니다. 셋째, 미래 위치를 가린 뒤 소프트맥스를 적용합니다. 넷째, 얻은 비율로 V들을 섞습니다. 다섯째, 결과를 원래 벡터 길이로 바꿔 잔차 스트림에 더합니다.

그림의 화살표를 아래에서 위로 따라가세요. Q와 K가 만나 비율을 만들고, V는 별도의 길로 올라와 그 비율과 만납니다. 그래서 ‘어디에서 가져올까’와 ‘무엇을 가져올까’를 구별하면 구조가 훨씬 이해하기 쉽습니다.

비율이 높다는 것은 해당 위치의 V가 가중합에 더 큰 계수로 들어간다는 뜻입니다. 이것만으로 그 토큰이 최종 답의 원인이라고 단정할 수는 없습니다. V의 내용과 출력 변환, 다른 헤드와 이후 계산도 영향을 줍니다. 처음에는 이 한계보다 계산 순서를 정확히 익히는 데 집중하세요.

확인 질문
어텐션 결과를 잔차 스트림에 더하기 전에 출력 변환을 하는 이유는 무엇인가요?
답변 예시
가져온 정보를 필요한 형태와 벡터 길이로 바꾸기 위해서입니다.

## 22. 문맥이 늘어나면 예측도 달라집니다

화면 설명

같은 모델도 앞에 주어진 말이 달라지면 다음 토큰의 확률이 달라집니다.

발표자 노트

각 그래프의 가로축은 다음 토큰 후보, 세로축은 모델이 계산한 확률입니다. 먼저 ‘The cat sat’ 다음을 예측한 그래프를 보고, 그다음 ‘on’과 ‘the’를 차례로 입력에 더한 그래프를 보세요. 문맥이 더 구체적이 되면서 유력한 후보가 달라집니다.

두 모델은 같은 문장을 보고도 다른 확률을 줄 수 있습니다. 학습 데이터, 가중치, 구조, 토크나이저 등이 다르기 때문입니다. 그래프에 보이는 후보는 일부이므로 막대들의 합이 반드시 1인 것은 아닙니다. 전체 어휘에 대한 확률을 모두 더해야 1입니다.

그래프마다 세로축의 범위도 확인하세요. 막대의 높이만 눈으로 비교하면 오해할 수 있습니다. 또한 한 예문에서 특정 후보의 확률이 더 높다고 해서 그 모델이 모든 과제에서 더 좋다는 결론을 내릴 수는 없습니다. 이 장의 목적은 입력 문맥과 모델에 따라 예측 분포가 달라진다는 점을 보는 것입니다.

확인 질문
‘The cat sat’ 뒤에 토큰 하나를 더 붙이면 남은 예측은 그대로일까요?
답변 예시
아닙니다. 새 문맥을 반영해 다음 토큰의 확률을 다시 계산합니다.

## 23. 구현할 때 확인할 텐서의 크기

화면 설명

각 화살표에서 숫자 배열의 크기를 확인하면, 어텐션 구현을 따라갈 수 있습니다.

발표자 노트

텐서는 숫자를 여러 축으로 배열한 것입니다. 벡터는 축 하나, 행렬은 축 두 개인 예입니다. 여기에 문장 묶음과 헤드 축을 더하면 세 축이나 네 축을 가진 배열이 됩니다. 축의 순서와 길이를 적어 두면 계산 실수를 줄일 수 있습니다.

이 그림에서 b는 문장 묶음의 크기, s는 토큰 수, e는 모델 벡터 길이, n은 헤드 수, h는 헤드 벡터 길이입니다. 입력은 보통 (b, s, e)입니다. Q, K, V를 만들면 헤드 축이 생기고, Q와 K의 비교 결과에는 질문 위치와 참고 위치라는 두 토큰 축이 생깁니다. 어텐션 비율은 보통 (b, n, s_q, s_k)로 생각할 수 있습니다.

V를 섞을 때는 참고 위치인 s_k 방향을 합칩니다. 질문 위치인 s_q는 남아야 합니다. 마지막에는 헤드 결과를 합쳐 (b, s, e)로 돌아갑니다. 구체적인 축 순서는 구현마다 다를 수 있으므로 einsum에 쓴 축 이름을 따라 확인하세요. 고해상도 원본 링크는 수식과 축 표기를 자세히 보는 참고 자료입니다.

확인 질문
어텐션의 결과에서 토큰 위치 축이 사라져야 하나요?
답변 예시
아닙니다. 각 질문 위치마다 결과 벡터 하나가 남아야 합니다.

## 24. 기본 구조 이후의 발전

화면 설명

오늘은 GPT2의 기본 흐름을 이해하면 충분합니다. 구조의 변형은 다음 단계입니다.

발표자 노트

이 장은 여러 후속 연구가 트랜스포머의 일부 계산을 바꾸어 왔다는 것을 보여 주는 참고 화면입니다. 논문의 영어 제목과 표지, 출처 이미지는 원문을 알아볼 수 있도록 유지했습니다. 지금 이 논문들을 읽어야 실습을 시작할 수 있는 것은 아닙니다.

이름을 가볍게 연결해 보면 GLU와 SwiGLU는 MLP 안의 정보 통과 방식을 바꾸는 계열이고, RoPE는 위치 정보를 반영하는 방식입니다. 전문가 혼합 구조는 입력에 따라 일부 계산 모듈을 골라 사용하는 방식입니다. 이들은 기본 구조를 익힌 뒤 비교하면 더 쉽게 이해할 수 있습니다.

오늘의 흐름을 자신의 말로 정리해 보세요. 글을 토큰 ID로 바꾸고, 임베딩으로 숫자 벡터를 얻습니다. 어텐션으로 문맥을 모으고 MLP로 가공하며, 잔차 연결로 결과를 쌓습니다. 마지막에 어휘별 점수를 확률로 바꾸고 다음 토큰을 선택합니다. 이제 실습에서 각 부품의 입력과 출력 크기를 확인하며 구현해 보면 됩니다.
